# Publishing the briefing page

The rendered `briefing.html` file is a self-contained interactive document with inlined figures, direct links to arXiv and alphaXiv, and feedback controls that write to the page's backing store. Publishing it as a private `claude.ai` artifact gives the reader a single persistent bookmark that works across desktop and mobile browsers while providing a database channel that returns stars, comments, question answers, and proposal decisions to the next run.

## First publish

Invoke the Artifact tool with the following parameters:

- `file_path`: `$RUN/briefing.html`
- `icon`: `newspaper`
- `description`: A one-sentence summary such as `"Daily arXiv research briefing generated by Aparture."`
- `capabilities`: `{ "db": {}, "sample": {} }`, where `db` stores reader events in the `feedback` collection and `sample` powers the per-paper `"Ask about it"` assistant box (if neither capability is available, the page renders in read-only mode).

Save the returned URL in `config.json` under `briefingArtifactUrl`, and run one verification call using ArtifactData `list` on the `feedback` collection for that URL (which returns an empty list on the initial run) before reporting the link to the reader.

## Every later run

Publish subsequent briefings to the existing `briefingArtifactUrl` so the reader's bookmark always opens the latest issue. Because a scheduled run executes in a new session, first read the existing artifact (`action: "read"`, `url: briefingArtifactUrl`) and then publish with `url: briefingArtifactUrl` and the new `file_path`, omitting `capabilities` and `icon` so the existing configuration carries forward. Republishing preserves the `feedback` collection across runs so earlier documents remain queryable by date and `ingest` appends only new or modified entries.

## What the page holds, and who can see it

The rendered HTML embeds the first ~1,500 characters of the reader's profile (to provide context for the `"Ask"` box) alongside each selected paper's deep-read report. The artifact is private to the reader by default; if the reader chooses to share the link, note that the embedded profile excerpt is included in the page source and that viewers without edit access can read the briefing in read-only mode.

## Without the Artifact tool

When the Artifact tool is unavailable, render `$RUN/briefing.html` with `--standalone` so it opens directly in any local browser, and report its file path to the reader. Reader feedback can then be given directly in chat and recorded during Phase 1 with `source: "chat"`.
